## TurboQuant의 KV 캐시 수치적 압축 — 상세 설명

### 1. KV 캐시가 무엇인가단계별로 설명합니다. 먼저 KV 캐시가 어떻게 생겼는지 직관적으로 보여드리겠습니다.### 2. 수치적 압축이란 무엇인가 — 핵심 개념

KV 캐시의 각 원소는 `0.3821044921875` 같은 부동소수점 실수입니다. 수치적 압축은 이 **숫자 자체의 비트 폭을 줄이는** 작업입니다. 특허의 JSON 압축이 "반복 문자열을 코드로 치환"하는 것과 달리, 수치 공간에서 "비슷한 값들을 하나의 대표값으로 묶는" 방식입니다.

다음 그림은 TurboQuant의 두 단계가 수치적으로 무엇을 하는지 보여줍니다.### 3. 기존 INT4 양자화가 왜 진짜 4비트가 아닌가

기존 방법의 핵심 문제는 **양자화 상수(quantization constants)** 입니다.

숫자 묶음을 압축할 때 "이 묶음에서 가장 큰 값이 얼마였는지"를 따로 저장해야 나중에 복원할 수 있습니다. 이것이 스케일(scale)과 제로점(zero point)입니다.

```
원본:  [0.38, -1.22, 0.91, -0.47]   → FP16 × 4 = 64 bits
INT4:  [  5,     1,    7,     3  ]   → 4비트 × 4 = 16 bits
scale: 0.2143                        → FP16       =  16 bits  (필수)
zero:  3                             → INT8        =   8 bits  (필수)
실제 총합:                                                 40 bits → 사실상 10 bits/값
```

TurboQuant가 이 오버헤드를 제거하는 방법은 **Random Rotation**입니다. 벡터를 무작위로 회전시키면 모든 좌표의 분포가 Beta 분포(고차원에서 정규분포에 수렴)로 균일해집니다. 분포가 이미 알려진 형태이므로, 최적 양자화 코드북을 한 번만 미리 계산해두고 매번 새로 저장할 필요가 없습니다.

### 4. "어텐션 계산에서 정확도를 왜 잃지 않나" — QJL의 역할

어텐션 스코어는 `Q · Kᵀ` 즉 내적(inner product)으로 계산합니다. MSE를 최소화하는 양자화는 내적 계산에서 편향(bias)을 만들어냅니다.

```
이상:   E[Q · K̃] = Q · K   (복원 벡터와 원본의 내적이 같아야 함)
현실:   E[Q · K̃] = (2/π) × Q · K   (1비트 양자화 시 2/π 배 편향 발생)
```

QJL은 Johnson-Lindenstrauss 변환을 이용해 이 편향을 수학적으로 제거합니다. 잔차에만 1비트를 쓰고, 복원 시 추정량(estimator)을 통해 내적의 기댓값이 원본과 동일하게 보정됩니다.

$$\mathbb{E}_Q[\langle y, Q^{-1}(Q(x))\rangle] = \langle y, x \rangle$$

이것이 "정확도 손실 0"의 수학적 근거입니다.

### 5. 특허 방식과의 비교 요약

| 구분 | 특허 (JSON 압축) | TurboQuant (KV 캐시 압축) |
|---|---|---|
| 압축 대상 | 반복 문자열 (텍스트) | 실수 벡터 (숫자) |
| 압축 원리 | 중복 패턴 → 짧은 코드 치환 | 고차원 실수 → 저비트 정수 매핑 |
| 사전(코드북) | 런타임에 동적 생성 | 오프라인에 한 번 계산, 재사용 |
| 오버헤드 | SUB-JSON 메타데이터 | 0 (회전으로 제거) |
| 복원 방식 | 코드 → 원문 역치환 | 역회전 + 추정량으로 내적 보정 |
| 정확도 | 완전 무손실 | 내적 기댓값 무편향 (수학적 보장) |

두 방법 모두 "메타데이터 오버헤드를 어떻게 줄이느냐"가 핵심 난제였고, 각자의 도메인에서 다른 방식으로 해결했다는 점이 흥미로운 대비입니다.
